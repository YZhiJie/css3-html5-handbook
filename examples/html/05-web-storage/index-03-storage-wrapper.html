Web 存储 示例 03 · 生产级封装

直接裸用 localStorage 会在真实项目里踩一堆坑：key 冲突、没有过期时间、隐私模式抛异常、脏数据解析崩溃。 本页演示一个 SafeStorage 封装如何一次性解决这四类问题——这也是文档第 2.5 节代码的可运行版本。

面板 1 · 命名空间隔离

两个模块各自 new 一个 SafeStorage（命名空间 cart / theme），用同名 key 存不同业务数据，互不覆盖；底层真实 key 是 "app:模块:key"。

面板 2 · 过期时间（3 秒 TTL）

写入一条 3 秒后过期的数据：过期前读到正常值；过期后 get 自动返回 null 并顺带删除底层条目（防冷数据堆积）。

（结果输出区）

面板 3 · 隐私模式降级（内存兜底）

构造一个"读写都抛异常"的假 Storage 来模拟隐私模式被禁用。SafeStorage 探测失败后自动切到内存 Map：本会话内照常读写，但刷新即失（真实项目应上报埋点）。

（结果输出区）

面板 4 · 脏数据安全解析

用户手动改过、版本升级、半截写入都可能产生非法 JSON。直接 JSON.parse 会抛错白屏；SafeStorage 把它收敛为"返回 null + 警告"。
