Web Locks API

跨标签页互斥 · 独占/共享锁 · 队列机制 · 自动释放

✅ 当前浏览器支持 Web Locks API，下方示例可直接运行。 ⚠️ 当前浏览器不支持 Web Locks API（需 Chrome 69+ / Firefox 72+ / Safari 15.4+）。

1. 独占锁 vs 共享锁

独占锁同时只能有一个持有者；共享锁允许多个读并发，但排斥写。 点击下方按钮观察日志——独占锁排队执行，共享锁并发执行。

当前持有：0
排队等待：0

独占锁回调执行 2 秒模拟写操作；共享锁回调执行 1 秒模拟读操作。观察两者的排队/并发差异。

2. ifAvailable：锁被占用时不排队，立即返回

先点击「占用锁 3 秒」，再点击「尝试获取」——锁被占用时立即返回 null，不排队。

适合「能拿就拿，拿不到就跳过」的场景，例如轮询更新缓存。

3. 跨标签页竞态：两个标签同时写 localStorage

在新标签页打开本页，两边同时点击「写入数据」。 无锁时互相覆盖；用 Web Locks 时排队执行，后写入的能看到先写入的结果。

无锁模式下两边同时 setItem，后执行者覆盖先执行者；有锁模式下 setItem 排队，后者读到前者的值后再写入，数据一致。

4. AbortSignal：取锁超时自动放弃

先点击「占用锁 5 秒」，再点击「带 2 秒超时的取锁」——超时后自动放弃，抛出 AbortError。
