示例 03 · :user-invalid 与自动填充

同款登录表单 ×2：上表单用 :invalid（加载即红，反面教材），下表单用 :user-invalid（交互后才红）+ touched 降级。指示灯显示实时校验状态。

观察要点：刷新页面后上表单"未输入就全红"；下表单全灰 —— 直到你输入过且失焦（或点过提交）。桌面 Safari ≤16.4 等旧浏览器只走下方降级路径。

方案 A · :invalid（反面教材）

CSS 只有 input:invalid 一条规则 —— 页面加载瞬间就命中，用户还没开始输入就被"红色风暴"包围。

:invalid 命中数：—

方案 B · :user-invalid（推荐）

新伪类只在"用户改过值且失焦"或"表单尝试提交"后命中；旧浏览器降级到 JS 的 .touched:invalid 组合。

※ 当前浏览器不支持 :user-invalid，正在走 .touched 降级路径。

状态：—
autocomplete 令牌与本页用到的字段： 账号 → username；邮箱 → email； 已有密码 → current-password（登录）；新密码 → new-password（注册/改密）； 短信验证码 → one-time-code（iOS 可从短信一键填充）。 这些令牌是密码管理器与系统填充的"翻译字典"，写对它们比写任何 placeholder 都更能提升填充成功率。
