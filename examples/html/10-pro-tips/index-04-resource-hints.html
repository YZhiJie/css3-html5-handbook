② loading="lazy" + fetchpriority + decoding：懒加载时机观察

下图全部是内联 SVG（data URI，零网络），属性按真实项目写法标注。 浏览器的原生懒加载内部也是"接近视口时才调度请求"——这里用 IntersectionObserver 把这个时机可视化：黄签=进入约 200px 预取范围， 绿签=真正进入视口。请向下滚动观察日志。

时机日志

  • loading="lazy"：接近视口才加载；首屏/LCP 图禁用（会拖慢 LCP）。
  • fetchpriority="high" 给 LCP 图；"low" 给首屏外的图；默认 auto。
  • decoding="async"：后台线程解码，大图解码不卡交互；属提示，浏览器可忽略。

③ 资源提示速查卡：<link rel> 五兄弟

dns-prefetch

只提前做域名解析（DNS）。

场景：第三方域多、廉价预热。

代价：极小，收益也最小。

<link rel="dns-prefetch"
      href="//cdn.x.com">

preconnect

DNS + TCP + TLS 全握手提前完成。

场景：3~4 个关键域（字体/API）。

代价：占连接、费电，过量反伤性能。

<link rel="preconnect"
      href="https://cdn.x.com"
      crossorigin>

preload

强制提前拉当前页必用资源。

场景：LCP 图、关键字体/CSS。

代价：没用上 → Console 报警 + 白耗流量。

<link rel="preload"
      href="/f.woff2" as="font"
      type="font/woff2"
      crossorigin>

prefetch

低优先级拉下一页可能用的资源。

场景：高概率的下一步导航。

代价：移动端浪费用户套餐流量。

<link rel="prefetch"
      href="/next-data.json">

modulepreload

预取并解析/编译 ES 模块。

场景：启动即依赖的模块链。

代价：同 preload，未用即浪费。

<link rel="modulepreload"
      href="/app.mjs">

noopener noreferrer

外链安全：新页面拿不到 window.opener。

场景：任何 target="_blank" 的外链。

代价：无；防 reverse tabnabbing。

<a href="https://x.com"
   target="_blank"
   rel="noopener
        noreferrer">

点此打开空白页测试（about:blank，不访问网络）↗

④ inputmode / enterkeyhint：移动端键盘增强（表单章补充视角）

🖥️ 桌面浏览器没有虚拟键盘，以下属性在桌面无可见效果——请用手机访问本文件（或真机/远程调试）点按输入框查看键盘变化。注意：它们不改变值类型，输入值仍是字符串。

inputmode="numeric"
enterkeyhint="next"

inputmode="decimal"
enterkeyhint="done"

inputmode="tel"
enterkeyhint="send"

inputmode="email"
enterkeyhint="search"

inputmode="url"
enterkeyhint="go"

inputmode="search"
enterkeyhint="search"

  • 取值：none / text / decimal / numeric / tel / search / email / url。
  • 与 type="number" 的区别：后者有数值语义（可能吞前导 0、带上下箭头）；验证码/金额优先 inputmode。

⑤ :-webkit-autofill 自动填充样式

浏览器自动填充时会强加淡黄色背景，普通 background 改不动；标准做法是用 -webkit-box-shadow: 0 0 0 1000px 品牌色 inset 内阴影盖住，再用 -webkit-text-fill-color 染文字。Firefox 另写 :autofill。
