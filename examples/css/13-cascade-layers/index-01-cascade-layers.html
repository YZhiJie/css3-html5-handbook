层叠层 Cascade Layers

@layer 显式定义样式优先级层级，终结 !important 战争与特异性军备竞赛。

示例 1 · 五层架构：reset → base → components → utilities

所有按钮共享同一 DOM 结构。btn-primary 和 btn-danger 在 utilities 层中用了 !important，能覆盖 components 层的背景色——因为层顺序在特异性之前决胜。

示例 2 · 层顺序 > 特异性（ID 选择器输给普通类）

low 层中用了 #specificity-test .btn-v2（ID + 类，特异性 (1,1,0)），high 层中只用 .btn-v2（特异性 (0,1,0)）。但 high 层声明顺序更晚，所以按钮是 青色 而非红色。层顺序比特异性更强。

示例 3 · 嵌套层：framework.reset / framework.components / my-overrides

嵌套层卡片
framework.components 提供基础样式，my-overrides 层覆盖边框颜色为紫色。
嵌套层语法：@layer framework { @layer reset { ... } @layer components { ... } }。外层声明顺序决定大方向，内层子层独立排序。

示例 4 · !important 在层中的逆序行为

这段文字是什么颜色？
base-imp 层：红色 !important；utilities-imp 层：绿色 !important。按层逆序规则，base-imp !important > utilities-imp !important，所以文字是 红色。
这防止了工具层用 !important 彻底封死下层覆盖——滥用 !important 时，层叠层不会给你免死金牌。

示例 5 · 层优先级可视化

@layer reset优先级最低（分层中）
@layer base↑
@layer components↑
@layer utilities↑
未分层规则（普通样式）优先级最高
记住：未分层 > 分层（按声明顺序后者优先）> 特异性 > 出现顺序。!important 在分层中按层逆序生效。
