① object-fit 五态对照

原图为 800×400（2:1）：内含九宫格刻度、四角标记与一个焦点圆，方便辨认拉伸/裁切方向。position 按钮对 cover / none 的效果最明显。

fill（默认）

拉伸填满，圆会变成椭圆、网格变形。视频/图片误用 100% 宽高时就是这个效果。

fill

contain

保持比例完整显示，短边方向留白（斜纹底）。商品图首选，绝不裁内容。

contain

cover

保持比例填满，长边裁切。封面/Banner/头像首选；裁切焦点听 object-position。

cover

none

不缩放，按原图 800×400 居中绘制，盒子小就只看得见中间一块。

none

scale-down

等同 none 与 contain 中"更小"的结果：小图不被放大、大图等比缩小。图片预览器常用。

scale-down

② 新写法 vs padding-top hack

两者视觉同高（16:9）。新写法里子元素正常文档流；旧写法用零高盒子 + 56.25% padding 撑高，子元素必须绝对定位。

aspect-ratio（现代）

width:100% · aspect-ratio:16/9 · 普通文档流

padding-top hack（兼容）

height:0 · padding-top:56.25% · 子元素 absolute

③ aspect-ratio 会被内容撑破（首选约束 ≠ 强制）

两个盒子都声明 1:1。左盒只给比例，大量文本直接把正方形撑成长方形；右盒加 overflow:hidden 才真正锁死（内容被裁，业务上需配套截断策略）。

只写 aspect-ratio（被撑破）

当内容高度超过比例推算高度时，min-height:auto 让内容优先，比例让步。这是与 padding hack 的硬高度最大的行为差异，实际使用要评估溢出策略。

aspect-ratio + overflow:hidden（锁死）

超出的文本被裁掉，盒子严格保持正方形。实际项目中文本行应配合第 10 章的 line-clamp，而不是简单裁掉。
