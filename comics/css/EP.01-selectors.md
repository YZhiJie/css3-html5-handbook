## 登场角色

- **像素酱**：CSS 造型师，本话主角。按钮颜色不听话，让她第一次见识了优先级的"隐形裁判"。
- **码叔**：划重点担当，只在知识条出镜，负责带走三句结论。

## 剧情梗概

两条规则同时选中一个按钮，写在前面的 `#nav .btn` 竟然赢了写在后面的 `.toolbar .btn`。像素酱顺着"谁说了算"往下挖，挖出了优先级三元组 (A, B, C) 这套计分规则，也顺手捡到了 `:is()` / `:where()` / `:has()` 三件现代武器。

## 分格解读

### 格1 · 痛点现场

`#nav .btn`（优先级 1, 1, 0）与 `.toolbar .btn`（优先级 0, 2, 0）抢同一个按钮。直觉上"两个类更具体"，但 **ID 在 A 位，逐位比较时 1 > 0 一票定胜负**——类位堆到 99 也翻不了盘。这就是"样式互相覆盖、只好堆 `!important`"的根源：优先级失控时，逃生舱被当成了常规武器。

### 格2 · 机制登场

优先级是一个三元组 **(A, B, C)**：A 数 ID，B 数类/属性/伪类，C 数元素/伪元素。比较规则是**逐位比较**，不是求和——`(1,0,0) > (0,99,99)`。三个细节常被忽略：

- `:not()` / `:is()` / `:has()` 本身不计分，但**括号里最复杂的参数计入**；
- `:where()` 无论括号里写了什么，**恒为 0**；
- 通配符 `*` 和组合器 `>` `+` `~` 空格**不产生任何优先级**。

### 格3 · 落地收束

现代逻辑伪类各司其职：

- `:is(section, article) h1` —— 合并重复前缀，一条顶三条，优先级取参数最高值；
- `:where(img, video)` —— 零优先级，写"默认层"样式，业务一行类选择器就能覆盖；
- `.form-group:has(input:invalid)` —— **父选择器**登场：父级感知子级状态，表单组整体标红，过去必须 JS 加 class 的场景现在零 JS。

## 码叔划重点

1. 优先级是 (A, B, C) 三元组，**逐位比较**，ID 一票定胜负。
2. 要覆盖用 `:where`（优先级 0），要合并用 `:is`（取最高参数），父级联动用 `:has`。
3. 浏览器**从右往左**匹配，关键选择器越短，引擎越省力——`ul li a span` 这种长链要避免。

## 自测一题

**问**：`:is(#a, .b)` 和 `:where(#a, .b)` 的优先级分别是多少？

**答**：前者取括号内最复杂参数，是 ID 级 (1, 0, 0)；后者恒为 (0, 0, 0)。所以"想要默认样式随便被覆盖"时，千万别把 `:is` 写成 `:where` 的替代品——口诀：**要覆盖用 :where，要合并用 :is**。
