## 登场角色

- **像素酱**：CSS 造型师，本话主角。给老后台系统接入新组件库，组件里的 `.title` 被全局上古规则污染，试过提特异性（再包一层又输回去）、Shadow DOM（把主题变量也挡在门外），进退两难。
- **标签君**：HTML5 结构师，搬出 `@scope`——规则只在圈内生效，`to` 挖出甜甜圈洞，两个圈打架时「谁离得近听谁的」。

## 剧情梗概

嵌套章（EP.28）收拢了「书写结构」，但像素酱发现嵌套只是把选择器写短，匹配范围仍然是全局的——样式照样泄漏。本话补上「作用域」这块拼图：`@scope` 给样式圈一块地盘，配合层叠层（EP.23）和嵌套（EP.28），「现代 CSS 架构」三部曲成型。

## 分格解读

### 格1 · 痛点现场

全局样式里的 `.title`、`a` 等上古规则无差别命中新组件。已有方案各有短板：提特异性是军备竞赛，Shadow DOM 隔离太彻底（字体、CSS 变量进不去），CSS Modules 绑死构建链。

### 格2 · 机制登场

`@scope (.card) { img {} }` 圈定子树，`@scope (.article) to (.widget)` 挖出甜甜圈洞——`.widget` 整棵子树免疫。两个作用域同时命中时启用「近距优先」：DOM 上离元素更近的根获胜，不比特异性不比书写顺序。关键细节：根选择器不参与特异性计算，`@scope (#app) { .btn {} }` 特异性仍是 (0,1,0)。

### 格3 · 落地收束

四大实战场景：组件样式圈地（BEM 长名瘦身回 `.title`）、富文本甜甜圈（排版规则绕开嵌入组件）、主题区域接管（两个主题并存互不污染）、第三方微件隔离（宿主页面零冲突，字体与变量照常继承）。

## 码叔划重点

1. @scope （根） to （限界）：圈内生效、甜甜圈挖洞，根选择器不抬特异性。
2. 近距优先：两个作用域同时命中时，DOM 上更近的根获胜。
3. 它不是 Shadow DOM：是低成本圈地，不是硬隔离，主题变量照常继承。

## 自测一题

**问**：`@scope (#app) { .btn { color: red; } }` 和手写 `#app .btn { color: red; }`，特异性一样吗？哪个更容易被业务方覆盖？

**答**：不一样。手写 `#app .btn` 特异性是 (1,1,0)（ID + 类），业务方要覆盖得写出更高特异性或同级更靠后的规则。`@scope (#app) { .btn {} }` 中根选择器不计入特异性，内部规则只有 (0,1,0)——业务方一条 `.btn { color: blue }` 同级规则按书写顺序即可覆盖。这正是 @scope 适合组件库的原因：**隔离命中范围，但不制造特异性霸权**。
